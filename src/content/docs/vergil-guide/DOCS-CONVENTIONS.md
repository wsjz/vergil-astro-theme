# 文档编写规范

这份规范约束 `src/content/docs/vergil-guide/` 下所有文档。它自己设了 `draft: true`，不会出现在站点上，只给写文档的人看。

规范的目的不是好看，是**防止文档慢慢烂掉**。过去这套文档出过的问题，每一条都对应下面一条规则。

## 一、命名

**文件名只用稳定的名词，不带任何会变的信息。**

```
好   媒体嵌入.md
坏   媒体嵌入（5个指令）.md
```

为什么：计数会过期（文件名写 5 个，实际早就不止），而且链接引用时容易漏掉后缀，导致 404。这套文档曾经因为这个命名，指令索引页的 5 个分类入口全部点不开。

**同理，标题和正文里不要写「共 N 个」这类总数**。想表达规模就说「按用途分为八类」，不要说「36+ 个指令」——代码里实际是 46 个，两处文档还各写了一个不同的数。

## 二、链接

**站内链接一律用绝对路径，不用相对路径。**

```
好   [博客写作](/docs/vergil-guide/03-基本创作/内容形式/博客写作/)
坏   [博客写作](./博客写作)
```

为什么：相对路径在三种情况下会断。

1. `_meta.md` 的 `homepage` 会把某篇文档渲染到知识库根路径，该文档里的相对链接就会少解析掉几层目录。这套文档的入口页四个主入口全是这样断掉的。
2. 文档 URL 会被转成小写，`./RSS订阅` 实际要访问 `rss订阅/`。
3. 同级还是子级容易写错，`边栏配置.md` 里写 `./Memo便签卡片` 会被解析成 `边栏配置/Memo便签卡片/`。

绝对路径前两种都不受影响。第一种要额外注意：**被 `homepage` 指定的那篇文档，自己的原路径不会生成**，它被渲染到了知识库根路径。所以链接它要写 `/docs/vergil-guide/`，写它的原路径必然 404。

写完跑一次链接检查（见第六节）。

## 三、order

**同一目录内 order 必须唯一且连续，从 1 开始，不留空号。新增文档插在中间就整体重排。**

不写 order 的文档会排到最后。这套文档的「数据统计」就因为漏写 order，被挤到了整章末尾。

## 四、内容

**只写代码里真实存在的东西。** 写配置字段前先去 `src/data/config/`、`src/content.config.ts`、`src/types.ts` 确认字段存在、名字对、默认值对。这套文档出过的反面教材：

- 教用户创建 `src/data/config/about.ts`，该文件不存在
- 教在文章 frontmatter 写 `commentsEnabled`，schema 里没这个字段，zod 静默丢弃
- 说 `statsPage.path` 可配，但没有任何代码读它
- 说 EXIF 支持 `model` 字段，schema 里没有

**描述默认行为前先验证。** 反面教材：说 mark 不传 color 默认主题色（实际默认黄色）、说 excerpt 不填自动取前 200 字（实际没有任何回退）、说草稿可以直接访问 URL 预览（实际 `getStaticPaths` 就过滤了，页面不生成）。

**代码示例必须能跑通。** 反面教材：`seo.image` 写成字符串，而 schema 要求 `{ src, alt? }` 对象，照抄构建直接报错。

**不要描述没实现的功能。** 反面教材：宣称相册支持 masonry / timeline / carousel 三种布局，实际 CSS 里只有 grid 的样式，另外三个值只落成 DOM 属性。

## 五、一致性

**包管理器统一用 pnpm**，仓库只有 `pnpm-lock.yaml`。例外是演示终端块效果、或讲第三方库安装的示例，那些保持原样。

**仓库地址、域名这类会变的信息只在一处出现**，其他地方引用它。反面教材：快速开始里的 clone 地址还指向 `justgoodui`（主题的上游作者），新用户第一条命令就拿到错的仓库。

## 六、改完要做的检查

改任何文档之后跑一遍：

```bash
pnpm build
```

然后确认：

- 新增或改名的文档出现在左侧目录树里
- 文档正文里的站内链接没有 404（对照构建产物里的真实路径，不要只查源文件是否存在——源文件存在不代表 URL 对得上）
- `:::callout` 这类指令真的渲染成了组件，而不是原样留成文本。注意语法是 `:::callout{...}`，冒号后**不能有空格**

## 七、什么时候必须更新文档

**改了用户可感知的行为，同一次改动里就要带上文档。** 包括：

- `src/data/config/` 下任何字段的增删改名
- `src/content.config.ts` 的 schema 变化
- 指令的名字、属性、默认值变化
- 默认开关状态变化

不要留到「以后补」。这套文档的代码最后提交是 9 月，文档最后提交是 6 月，中间三个月的十来个新特性一个字都没写，就是这么攒出来的。
